# 2026名古屋亞帕運中繼站簡易預約系統

給**中繼站總控工作人員**在同一台電腦上使用的內部簡易預約登錄工具。工作人員每天登錄各代表隊提出的服務預約（餐食／交通接駁／防護治療／體能訓練／運科支援），確認無誤後可依日期匯出 Excel，交由後續人員進行實際派車、備餐、安排場地等作業。

這是一個**純前端網站**：沒有登入機制、沒有 Supabase／Firebase、沒有雲端資料庫、不支援多人即時同步。所有資料只會存在您目前使用的這台電腦、這個瀏覽器的 `localStorage` 裡，重新整理或關閉瀏覽器後資料仍會保留，但換一台電腦或清除瀏覽器資料就會遺失，**請每日匯出 Excel，並定期使用「資料備份」下載 JSON 備份檔**。

與既有的「Excel匯入型管理工具」（`nagoya-relay-shuttle-tool2026`）完全獨立，本次建置**沒有修改**該專案的任何檔案。

---

## 一、基本操作流程

打開網站後預設進入「新增預約」頁：

1. **新增預約**：填寫預約日期、代表隊、服務項目、預約人數，再依服務項目顯示對應的專屬欄位，填完後按「下一步：確認」。
2. **預約確認**：畫面會完整顯示這筆預約的所有內容，並自動檢查同一時段的容量是否超過限制。沒有問題就按「確認新增」正式儲存；如果想修改就按「返回修改」。
3. 儲存後可以在「每日預約總覽」用日期／代表隊／服務項目／關鍵字篩選檢視所有預約，並對每一筆做「查看」「修改」「複製」「刪除」。
4. 每天作業告一段落後，到「Excel 匯出」選擇日期，按「匯出當日預約」下載當天的 Excel 清單，交給後續人員安排派車、備餐等作業。
5. 定期到「資料備份」下載 JSON 備份檔，避免瀏覽器資料被清除後無法復原。

「預約」與「確認」只是操作上的兩個步驟，系統**不會**額外設計「待確認／已確認／已完成」等預約狀態欄位——預約一旦按下「確認新增」就是正式資料。

## 二、預約單編號規則

- 格式固定為 `RYYMMDD-XXX`，例如 2026-10-12 當天的第一筆是 `R261012-001`，第二筆是 `R261012-002`。
- 編號完全由系統自動產生，畫面上不會讓使用者手動輸入或修改。
- 每個日期各自從 001 開始計算，依「當日已存在的最大流水號」往下產生下一號。
- **刪除舊預約後，該編號不會被重新使用**：系統會另外記錄每個日期「歷史上使用過的最大流水號」，即使把某筆預約刪除，下一筆新增仍會接續在歷史最大號之後，不會產生重複或跳號回收的編號。
- 「複製」某筆預約時，會複製除了編號以外的所有欄位內容，並在確認新增時重新產生一個全新的預約單編號。

## 三、代表隊與服務項目

代表隊下拉選單固定為：射箭、田徑、羽球、地板滾球、柔道、健力、射擊、游泳、桌球、跆拳道、輪椅擊劍、輪椅網球，另外加上「中繼站工作人員」與「其他」；選擇「其他」時會顯示文字輸入欄位，供自行輸入代表隊或單位名稱。

服務項目共 5 種，選擇後才會顯示對應的專屬欄位：

| 服務項目 | 專屬欄位重點 |
|---|---|
| 餐食 | 餐別（午餐／晚餐）、用餐或送餐時間、餐食份數、供應方式（中繼站用餐／送至比賽地點／自取）、地點、餐食內容或特殊需求、素食份數 |
| 交通接駁 | 接駁類型（單程／來回）、去程上下車時間地點、乘車人數、是否需要福祉車、輪椅使用人數、乘車人員或隊伍說明；選「來回」時另外顯示回程資訊 |
| 防護治療 | 分支項目（防護處置與物理治療／按摩床使用空間／醫師治療）、開始結束時間、預約人數、需求說明 |
| 體能訓練 | 分支項目（肌力體能訓練）、開始結束時間、預約人數、訓練需求 |
| 運科支援 | 分支項目（生理生化檢測／氣壓式按摩機／加壓艙／個別會談／營養諮詢）、開始結束時間、預約人數、需求說明 |

交通接駁的地點下拉選單固定為「比賽地點」「選手村（飯店）」「名古屋中繼站」，如有特殊地點可選「其他」並自行輸入文字。**交通接駁只負責蒐集需求，系統不會自動排車或指派車輛**，畫面上會提示目前可用車輛為一般車輛 4 台（每台最多 9 人）與福祉車 1 台，這只是給填寫人員參考的文字說明，不會被系統用來做任何自動判斷。

## 四、時段容量檢查規則

防護治療、體能訓練、運科支援的人數限制，是「**同一時段的總容量**」，不是單筆預約各自的人數上限：

| 服務／分支 | 同一時段容量 |
|---|---|
| 防護治療－防護處置與物理治療 | 3 人 |
| 防護治療－按摩床使用空間 | 2 人 |
| 防護治療－醫師治療 | 無上限（不阻擋，僅提示同時段已有其他醫師治療預約） |
| 體能訓練－肌力體能訓練 | 10 人 |
| 運科支援－生理生化檢測 | 5 人 |
| 運科支援－氣壓式按摩機 | 12 人 |
| 運科支援－加壓艙 | 5 人 |
| 運科支援－個別會談 | 2 人 |
| 運科支援－營養諮詢 | 2 人 |

在「預約確認」步驟，系統會用**時間事件分段掃描（time-sweep）**演算法，計算「這筆新預約時間範圍內，每一個實際時間區段」的最高同時使用人數，而不是把所有「與新預約有重疊」的既有預約人數整個加總——這兩者在既有預約彼此沒有同時重疊時會得出不同結果。例如容量 3 人時，若既有預約 A（09:00–10:00，2人）與 B（11:00–12:00，2人）本身沒有重疊，新預約是 09:00–12:00（1人），實際最高同時人數只有 3 人（A+新，或 B+新，A、B 不會同時出現），系統會正確判斷為未超量，允許確認新增。

規則：

- 開始時間計入、結束時間不計入（區間為 `[start, end)`），因此 09:00-10:00 與 10:00-11:00 視為前後相鄰但不重疊，不會互相影響同時人數；09:00-10:00 與 09:30-10:30 才算重疊。
- 只有當某一個實際時間區段的同時使用人數「真正超過」容量上限時才會阻擋，而不是憑總和判斷。
- 畫面上的紅色警示會清楚列出「真正超量的時間區段」及該區段當下的總人數，並附上造成超量的既有預約（單號、代表隊）。
- **「確認新增」按鈕會停用**，無法儲存，需要調整時間或人數後才能繼續。
- 修改既有預約時也會用同樣的邏輯重新檢查，並自動排除自己這一筆。
- 醫師治療不受容量規則阻擋，只會提示同時段已有其他醫師治療預約。

## 五、每日預約總覽

上方提供日期選擇、代表隊篩選、服務項目篩選、關鍵字搜尋（會比對預約單編號、代表隊、聯絡人、聯絡方式、備註）。

下方統計卡片顯示當日：全部預約筆數、餐食總份數、**交通接駁人次**（去程人數＋回程人數相加，因此稱為「人次」而不是「人數」）、防護治療總人數、體能訓練總人數、運科支援總人數。

預約列表依開始時間排序，不同服務用不同淡色背景快速辨識。「人數」欄位：交通接駁顯示**去程乘車人數**為主要人數，如果是來回接駁且去程／回程人數不同，會顯示「去程X人／回程Y人」；其餘服務顯示共用的「預約人數」欄位。每筆資料可以「查看」（彈出視窗顯示完整內容）、「修改」（回到表單重新編輯，儲存後保留原本的預約單編號）、「複製」（帶著原本內容進入新增流程，但會產生全新編號）、「刪除」（需要勾選確認後才能刪除，避免手滑誤刪）。

### 人數欄位的主要數量說明

- **餐食**：以「餐食份數」作為這筆預約的主要數量；素食份數不得大於餐食總份數。
- **交通接駁**：以「去程乘車人數」作為這筆預約的主要人數（畫面上不再另外顯示共用的「預約人數」欄位，避免兩個數字不一致）；來回接駁的回程人數可以跟去程不同；輪椅使用人數不得大於去程乘車人數。
- **防護治療／體能訓練／運科支援**：仍使用共用的「預約人數」欄位進行容量判斷，不受本次調整影響。
- 所有人數、份數欄位都必須是整數。

## 六、Excel 匯出

在「Excel 匯出」頁選擇日期，按「匯出當日預約」，會用 **ExcelJS** 產生 `.xlsx` 檔案，檔名格式為 `2026-10-12_亞帕運中繼站預約清單.xlsx`。

每份 Excel 固定包含 6 張工作表，即使當天某項服務完全沒有預約，工作表也會保留並顯示「本日無預約資料」：

1. **每日預約總表**：序號、預約單編號、日期、開始時間、結束時間、代表隊、服務項目、分支項目、預約人數、聯絡人、聯絡方式、需求內容、備註（依開始時間排序）。
2. **餐食**：序號、預約單編號、代表隊、餐別、時間、供應方式、地點、餐食份數、素食份數、餐食內容或特殊需求、聯絡人、備註，最下方顯示午餐總份數、晚餐總份數、素食總份數、全日總份數。
3. **交通接駁**：序號、預約單編號、代表隊、去程/回程時間地點與人數、是否需要福祉車、輪椅使用人數、乘車人員或隊伍說明、聯絡人、備註，另外保留「車輛安排」「派車備註」兩欄空白，供匯出後由人工排車時填寫（系統本身不做自動排車）。
4. **防護治療**／5. **體能訓練**／6. **運科支援**：序號、預約單編號、開始時間、結束時間、代表隊、分支項目、預約人數、需求說明、聯絡人、聯絡方式、備註。

版面設計：

- 第一列顯示「2026名古屋亞帕運中繼站預約清單」標題，第二列顯示日期與匯出時間。
- 欄位標題採橘色底、白色粗體字。
- 所有儲存格加框線、內容自動換行、垂直置中。
- 凍結標題列（往下捲動時標題列固定在畫面上方）。
- 版面設定為橫向列印、縮放成一頁寬，並自動設定列印範圍，適合 A4 直接列印。
- 欄寬依內容預先調整，長內容不會被截斷（透過自動換行呈現）。
- 「每日預約總表」的交通接駁人數，與「交通接駁」分頁的（去程）人數一致。

### 日期／時間欄位格式

六張工作表中所有的日期與時間欄位，都是寫成 **Excel 可以直接辨識的日期／時間值**（date/time cell，套用 number format `yyyy-mm-dd` 與 `hh:mm`），不是純文字字串：

- 可以在 Excel 裡直接依日期或時間欄位排序，會依照真正的時間先後排序，而不是依字串排序。
- 畫面顯示格式固定為 24 小時制（例如 `14:30`，不會出現 AM/PM）。
- 如果某筆預約沒有結束時間（例如餐食、交通接駁的單程沒有回程時間），對應儲存格會保持**完全留白**，不會被誤轉成錯誤的日期或時間。

## 七、資料備份與安全

- **備份全部資料**：在「資料備份」頁按「下載備份（JSON）」，會把目前所有預約資料連同編號流水號紀錄一起打包成 JSON 檔下載。
- **從 JSON 匯入備份**：選擇備份檔後，畫面會先顯示這份備份檔案的資料筆數與日期範圍，接著可以選擇：
  - **合併匯入**：保留目前資料，只加入備份檔裡「預約單編號」還沒出現過的預約；相同編號的預約不會重複匯入，匯入完成後會顯示新增與略過的筆數。
  - **取代現有資料**：完全用備份檔內容覆蓋目前瀏覽器裡的所有資料。
- **清除本機資料**：需要在文字框輸入「確認清除」四個字才能按下清除按鈕，避免手滑清空資料；清除前請務必先下載備份。
- 首頁（新增預約頁）頂端會持續顯示提醒：「本系統資料儲存於目前瀏覽器，請每日匯出 Excel 並定期下載資料備份。」

### localStorage 保存方式說明

系統把所有預約資料存成一個 JSON 物件，寫入瀏覽器的 `localStorage`（鍵名 `nagoya-parapan-reservation2026:data:v1`），內容包含目前所有預約清單，以及每個日期「歷史上用過的最大流水號」。`localStorage` 是瀏覽器內建、不需要任何伺服器的本機儲存空間，資料只會留在「這台電腦＋這個瀏覽器」上，關閉分頁、重新整理都不會遺失，但換瀏覽器、換電腦、或使用者自行清除瀏覽器資料（包含清除瀏覽紀錄/Cookie）就會遺失，所以務必養成定期下載 JSON 備份、每日匯出 Excel 的習慣。

## 八、給部署人員：怎麼把這個工具放上網（GitHub Pages）

### 1. 建立 GitHub Repo

```bash
cd nagoya-parapan-reservation2026
git init
git add .
git commit -m "first version: simple reservation system"
git branch -M main
git remote add origin https://github.com/<您的帳號>/nagoya-parapan-reservation2026.git
git push -u origin main
```

### 2. 開啟 GitHub Pages

到 repo 的 Settings → Pages，Source 選擇「GitHub Actions」（不是選分支）。本專案已內建 `.github/workflows/deploy.yml`，只要 push 到 `main` 分支就會自動建置並部署，幾分鐘後網址就能打開（網址格式：`https://<您的帳號>.github.io/nagoya-parapan-reservation2026/`）。

### 3. 如果直接用 GitHub 網頁版上傳（不使用 git 指令）

把整個解壓縮後的專案資料夾內容（`src/`、`public/`、`.github/`、`package.json`、`vite.config.ts`、`tsconfig.json`、`tailwind.config.ts`、`postcss.config.mjs`、`index.html`、`.gitignore`、`README.md` 等）上傳到您的 repo 根目錄，之後同樣到 Settings → Pages 選擇「GitHub Actions」即可，後續每次覆蓋上傳新檔案並確認 commit 成功，GitHub Actions 就會自動重新建置部署。

### 4. 本機開發

```bash
npm install
npm run dev
# 開啟 http://localhost:5173
```

`npm run build` 會先做型別檢查（`tsc --noEmit`）再打包，`vite.config.ts` 裡的 `base` 要跟 repo 名稱一致（`/repo名稱/`），如果改了 repo 名稱記得同步修改這裡。本專案使用 `HashRouter`（網址會帶 `#/new`、`#/overview` 這種井字號），確保 GitHub Pages 重新整理或直接輸入網址時不會出現 404。

部署到 GitHub Actions 時，`.github/workflows/deploy.yml` 使用 `npm ci`（依照 `package-lock.json` 做完全一致的安裝），因此 `package-lock.json` 一定要跟著 commit 進版本控制，不能只 commit `package.json`。

### 4.1 執行端對端自動化測試（開發／驗收用，非必要）

`scripts/verify-e2e.mjs` 是用 Playwright 寫的驗證腳本，不隨網站一起部署，純粹是開發或驗收時用來確認功能是否正常的工具。第一次使用前需要先下載 Playwright 自行管理的 Chromium：

```bash
npm install -D playwright
npx playwright install chromium
npm run build
npm run preview -- --port 4174 --strictPort   # 另開一個終端機視窗，保持執行中
node scripts/verify-e2e.mjs                   # 再開一個終端機視窗執行
```

腳本預設會使用 `npx playwright install chromium` 下載、由 Playwright 自行管理的瀏覽器，不需要額外設定。若在某些特殊環境（例如企業內網、容器）需要改用自訂路徑的 Chromium 執行檔，可以設定環境變數 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指向該執行檔，腳本會優先使用這個路徑；一般使用者不需要設定這個環境變數。

### 5. 產生測試用範例資料

```bash
npm run generate:sample-data
```

會在專案根目錄產生 `亞帕運中繼站預約系統_範例資料.json`，可以到「資料備份」頁的「從備份還原」上傳這個檔案測試匯入功能（本次交付內容已附上一份現成的範例檔案）。

**已知限制**：

- 本系統為單機單使用者設計，不支援多人同時在不同瀏覽器/電腦上共用同一份資料（沒有雲端同步），如果總控人員換電腦作業，需要先用「資料備份」匯出、再到新電腦匯入。

- 沒有任何帳號機制，只要能開啟這個網址就能使用；若未來需要限制存取範圍，建議額外討論（例如放在內部網路或加上簡單的存取密碼）。
